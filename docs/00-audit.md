## Что оставляем
- Данные программы `src/data/program.js` — 6 сессий (день 1: 10:10–11:40, 12:00–13:30, 14:30–15:50, 16:20–17:40; день 2: 10:30–12:00, 12:20–13:50) совпадают с ТЗ; в финальную версию всё равно перевыгружаем с сайта скриптом 05, это только сверка.
- Наработки по a11y/fallback: `prefers-reduced-motion`, `?mode=classic`, skip-link.
- Паттерн «один canvas + мастер-прогресс + Lenis»: те же принципы нужны в v2, но управление переписывается (магнитные остановки, раскадровка относительно якорей).
- Отель по OSM из v5 (`goldenhorn.json`): 43.1122° N, 131.8929° E — **стартовая гипотеза** для `01_resolve_anchors.py`, не истина.
- Шрифт Onest (кириллица, строгий гротеск) и JetBrains Mono — подходят под раздел 8; лицензия OFL. Сверить с шрифтом bankrufeast.ru.

## Что переписываем
- **Всё представление города**: меши/шейдеры v3 (цветные, закат, «ночной город» instancing) → облако точек + контуры + проявление по фокусу (разд. 6).
- **Всю информационную подачу**: HTML-слои `layers/*.js` → носители A–D (SDF-текст, выноски CSS2D, поверхностные надписи, живые объекты); HTML только для E.
- **Камеру**: ключи по главам → остановки относительно якорей, магнитность, ограничение угловой скорости, проверка коллизий.
- **Палитру**: убрать amber/coral/синие градиенты; один акцент (зелёный Сбера) на `#07090B`.
- **Данные города**: v3 — условный рельеф из гауссиан; нужны реальные OSM + DEM (скрипты 01–04).
- **Контент**: портреты в v3 — заглушки; нужны 24 реальных фото с bankrufeast.ru (сейчас не проверено, что сайт отдаёт их стабильно).
- **Стили**: `backdrop-filter`, скругление 22 px, «пилюли» (`border-radius: 999px`), плавающие карточки — запрещены разделом 8.

## Риски, найденные в аудите
1. Карточки сессий и спикеров в v3 — главный антипаттерн v2; их нельзя «подкрасить», только заменить.
2. Объём работы: M2 (реальные OSM/DEM-данные) — отдельный большой блок; OSM-данные Золотого моста и Русского моста нужно проверять на качество геометрии вручную.
3. Недоступность внешних источников (Overpass, DEM, bankrufeast.ru) из окружения не проверена; скрипты придётся кэшировать в репозиторий.
4. Требование «24 спикера» проверится только после парсинга; v3 показывает 24 записи, но с заглушками.
